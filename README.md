# OPW2 Probe

Диагностический APK для OnePlus Watch 2 (Wear OS 4). Ничего не будит — только собирает факты,
по которым проектируется умный будильник.

## Что делает

1. **Сенсоры** — полный дамп `SensorManager`: имена, `stringType`, вендор, FIFO, min/max delay,
   поиск HRV/PPG/RR-сенсоров. Плюс `BOARD/DEVICE/MODEL/SDK`.
2. **Health Services** — capabilities `PassiveMonitoringClient` (какие типы данных реально
   поддерживает OPW2: HR, HRV, SpO2, skin temp, активности) через рефлексию, поэтому APK не
   падает на несовпадении версий API.
3. **Health Connect** — статус провайдера, выданные разрешения, чтение `SleepSessionRecord`
   за 30 дней (если OHealth пишет туда сон — увидим этапы и интервалы).
4. **Ночной лог** в двух режимах:
   - `ЭКОНОМ`: акселерометр 25 Гц (батчинг 5 с) + пульс 40 с каждые 5 минут;
   - `ПОЛНЫЙ`: то же, но пульс 40 с каждую минуту.

CSV на бакет 30 с: батарея, зарядка, температура батареи, экран, doze, пульс и его возраст,
`n/mean/std/p2p` магнитуды акселерометра, число «рывков», число сэмплов пульса, uptime.

С версии `1.9-p0` в CSV добавлены три колонки для диагностики ночи:

| колонка | смысл |
|---|---|
| `hr_source` | `sensor` — свой `TYPE_HEART_RATE`, `passive` — Health Services, `none` — данных нет |
| `saw_asleep` | подтверждён ли сон (косвенно, по тишине + стабильному HR) |
| `alarm_state` | `idle` / `armed` / `triggered` |

Файлы пишутся в `getExternalFilesDir(null)`:
`/sdcard/Android/data/io.github.smartalarm/files/probe_<mode>_<ts>.csv` + `summary.txt` +
`report_*.txt`.

## Экран приложения (дизайн v3: язык v1 + исправленная геометрия, с `1.71-ui`)

Иконка в лончере открывает приложение на разделе **1 «Будильник»**. Визуальный язык, токены,
карта экранов и чек-лист приёмки — [`docs/design-v3.md`](docs/design-v3.md).

> Направление «Ночной инструмент» (`docs/design-v2.md`: янтарь, шкала-обод, волосяные линейки,
> дуга-рычаг) было **отклонено владельцем проекта** — прежний язык читается лучше. Возвращены
> бирюзовый акцент, градиентный фон, карточки и капсулы, кнопка-капсула и крупное время в центре;
> исправления геометрии и состояний из редизайна сохранены.

Три раздела, листаются свайпом влево/вправо по кругу (1 → 2 → 3 → 1):

- **1 «Будильник»** — кольцо прогресса по краю, крупное время цели в центре (тап по циферблату —
  редактор времени, долгое нажатие — «Ночь»), статус словами (`НЕ ВЗВЕДЁН` / `СЕГОДНЯ · 7Ч 12М` /
  `ЗАПИСЬ · 84%` / `НЕТ ПРАВ`), капсула окна и повтора (тап — окно 15/30/45/60, долгое нажатие —
  повтор по дням) и одна главная кнопка-капсула: «СПАТЬ» → «НАЧАТЬ ЗАПИСЬ» → «ОСТАНОВИТЬ».
- **2 «Ночь»** — карточка с графиком последней ночи: полоса фаз, линия пульса с заливкой, столбики
  движения и отметка срабатывания будильника; под ней легенда, фаза подъёма (20 px), сводка двумя
  строками и две плашки метрик с числом 44 px. Скролла нет — вся первая страница влезает в круг.
- **3 «Статус»** — карточки-строки по 72 px (36 dp, тап-зона по R3) с прокруткой: будильник, повтор,
  отложить, ночной лог, последний подъём, батарея, разрешения, версия.

AOD/ambient не поддерживается: это приложение (будильник + ночной лог), а не циферблат —
экран гаснет по системному таймауту. Центральный блок главного экрана (статус → капсула окна
→ кнопка) собран компактно и целиком лежит внутри кольца, не заезжая на дугу.

Проверка вёрстки на часах без «глаз»: `tools/verify-ui.ps1` (adb-дамп UI + скриншот, считает
для каждого узла расстояние углов до центра и печатает FAIL при выходе за 209 px).

## Надёжность (с `1.11-alarm`)

Измеренная проблема: при работающем FGS `Wake Locks: size=0`, `mWakefulness=Asleep`, и
`Handler.postDelayed` (считается по uptime, который в suspend не идёт) срабатывает с
задержкой 39–121 с вместо 30; за ночь покрытие падало до 21 %.

Что сделано:

- **Heartbeat.** `HeartbeatReceiver` — точный `setExactAndAllowWhileIdle` каждые 60 с.
  Пока сервис жив, он просит немедленный сброс бакета (`ACTION_FLUSH`); если сервис умер —
  поднимает его заново (allowlist от alarm разрешает старт FGS из фона).
- **Звук.** `AlarmPlayer` кроме вибрации играет тон на `STREAM_ALARM` (у OPW2 есть динамик).
  Вибрация — паттерн с паузами, потому что амплитудой управлять нельзя
  (`hapticChannelMaxAmplitude=0.0`).
- **Один будильник, не два.** `AlarmLogic.markFired()` дедуплицирует срабатывание:
  дедлайн из сервиса и `AlarmManager` приходят почти одновременно.
- **Защита от случайного выключения.** На экране будильника кнопка срабатывает только
  по удержанию, кнопки часов будильник не гасят. Авто-стоп — 5 минут вместо 90 секунд.
- **Перевзвод.** `BootReceiver` обрабатывает `BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`,
  `TIME_SET`, `TIMEZONE_CHANGED` и восстанавливает будильник из `Prefs`.
- `AlarmClockInfo.showIntent` теперь activity, а не broadcast — системный UI видит будильник.
- `tools/morning.ps1` — утренний сбор: выгрузка, прогон `night_report.py`, история срабатываний.

## Проверка ночи

`tools/night_report.py` считает, годится ли ночь для анализа, и возвращает код 1, если нет:

```bash
python tools/night_report.py --latest /sdcard/Android/data/io.github.smartalarm/files
python tools/night_report.py probe_eco_*.csv --min-coverage 95 --min-hr 90
```

Пороговое условие: покрытие ≥95% (строки против ожидаемых 30-секундных бакетов) и ≥90% окон
со свежим пульсом (`hr_samples>0` и `hr_age_s<=300`). Отдельно печатаются провалы >90 с, доля
подтверждённого сна, состояние будильника и расход батареи на участках без зарядки.

## Сборка

GitHub Actions, без локального SDK. Каждый пуш в `main` собирает `app-debug.apk`
и обновляет релиз `nightly`.

## Установка на часы

На часах: Настройки → Система → О телефоне → 7× «Номер сборки» → Для разработчиков →
«Отладка по Wi-Fi» (записать `IP:порт` и код сопряжения).

```bash
adb pair <IP>:<PAIR_PORT> <CODE>
adb connect <IP>:<ADB_PORT>
adb install -r opw2-probe.apk
adb shell am start -n io.github.smartalarm/.ProbeActivity
```

Забрать данные:

```bash
adb shell ls /sdcard/Android/data/io.github.smartalarm/files/
adb pull /sdcard/Android/data/io.github.smartalarm/files/ ./probe-data/
```

## Ночной протокол

1. Надеть часы плотно, выключить always-on display, поставить на зарядку НЕЛЬЗЯ —
   мерим расход от батареи, зарядить до 100% перед сном.
2. Открыть приложение, выдать разрешения, нажать «Старт: ЭКОНОМ» (или «ПОЛНЫЙ»).
3. Утром — «Стоп лог», затем выгрузить файлы через adb.
4. Для сравнения режимов нужно 2 ночи (по одной на режим), в идеале на одинаковом заряде.

## Кнопки после обновления

- **8 Сводка по последнему логу** — агрегаты прямо на часах: длительность, дельта батареи,
  сколько сэмплов пульса, min/avg/max HR, пустые окна акселерометра, окна с движением, doze.
  Позволяет снять результат без adb (сфотографировать экран).
- **9 Тест будильника через 2 мин** — ставит `setAlarmClock`, пишет маркер в
  `alarm_fired.txt`. Проверка: сработает ли системный будильник, если часы ушли в Power Saver.
- **4b ЭКОНОМ без wakelock** — тот же лог, но без `PARTIAL_WAKE_LOCK`: проверяем, выживает ли
  сервис на аппаратном батчинге сенсоров и сколько экономит.

## Ограничение: сырой PPG

Решающий эксперимент (60 с, контакт, ACCURACY_HIGH, истинный HR 82–93) показал, что в `PPG_RAW_*` нет кардио-компоненты — подробности и цифры в [docs/ppg-findings.md](docs/ppg-findings.md). Рабочий план для «умности»: passive HR + актиграфия.
