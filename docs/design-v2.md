# Дизайн v2: «Ночной инструмент» (Night Instrument)

Устройство одно и навсегда: **OnePlus Watch 2 (OPWWE231)**, круг **466 × 466 px**, 320 dpi,
1 dp = 2 px, центр **(233, 233)**, безопасный радиус контента **209 px** (`R − 24`).
Правила геометрии и ввода — `docs/skills/wear-os-ui.md` (R1–R13). Этот файл — источник правды
по визуальному языку; старые `docs/design-tokens.md` и `docs/design-brief.md` считать историей.

---

## 1. Концепция

**Одна фраза.** Часы — это ночной инструмент: **гравированная шкала, тлеющий янтарь и бумажный
шрифт; экран отвечает не «который час», а «когда подъём».**

### 1.1 Семь принципов

1. **Прибор, а не дашборд.** Ни одной карточки, тени, «капсулы» или скруглённого прямоугольника.
   Только три сущности: волосяная линейка (1 px), шкала и свет. Скругление есть лишь у дуг —
   потому что дуга и есть радиус.
2. **Шкала вместо прогресс-бара.** Время кодируется **позицией на 12-часовой шкале**, а не процентом.
   Кольцо «сколько прошло от 12 часов» (старый дизайн) не сообщало ничего; шкала сообщает
   «где на циферблате мой подъём» и «сколько дуги осталось до него».
3. **Один источник света.** Единственный акцент — янтарь `#FFA24C`. Всё остальное — уголь,
   пепел и бумага. Фазы сна кодируются **высотой и яркостью, а не оттенком**: глубокий — полный
   янтарь, лёгкий — притушенный янтарь, бодрствование — волосяная черта. Один цвет, много уровней
   света → язык остаётся одноцветным и читается в ч/б и при дальтонизме.
4. **Будущее в центре, настоящее на краю.** Герой экрана — **время подъёма** (крупно, 104 px),
   текущее время — тонкая строка сверху (36 px). Старый дизайн ставил в центр «сейчас» и прятал
   главный факт ночи в подпись 11 sp.
5. **Действие — дуга у обода.** Главная кнопка — **сегмент обода** (annulus-сектор), а не
   прямоугольник. Это не украшательство: в нижней полосе круга доступная ширина падает до
   ~140 px, а дуга там живёт естественно и растёт вместе с радиусом. Прямоугольник в этой зоне
   либо узкий, либо вне круга.
6. **Механика вместо плавности.** Никаких fade. Движение = следование за пальцем, доводка
   за 180 мс, смена значения — **детент** (мгновенно + хаптик), дыхание янтаря только при записи.
7. **Тишина в AOD.** В покое на экране остаются два времени, тонкая дуга и шкала; ни кнопок,
   ни подписей, ни анимаций; обновление раз в минуту.

### 1.2 Чем отличается от прежнего дизайна

| | Было (v1) | Стало (v2) |
|---|---|---|
| Метафора | «тёмный экран с кольцом» | гравированный ночной инструмент |
| Акцент | бирюза `#00D1A9` + градиент `#22E0B4→#00A9C0` | янтарь `#FFA24C`, без градиентов, свет через прозрачность |
| Герой | текущее время 96 px | **время подъёма** 104 px + строка «сейчас» 36 px |
| Прогресс | кольцо 16 px на весь экран, % от 12 ч | **шкала 72 риски + дуга отсчёта** 4 px по ободу |
| Контейнеры | карточки radius 12–16 dp, обводка 2 px | **волосяные линейки 1 px**, карточек нет |
| Главное действие | капсула 200×96 с градиентом | **дуга-рычаг у обода** 34 px, текст по дуге |
| Фазы сна | 4 разных цвета (нарушение «одного акцента») | один янтарь: глубина = высота + яркость |
| Индикатор разделов | 3 точки внизу (наезжали на контент, убраны) | **3 риски вверху**, y 60–72, на всех экранах |
| Типографика | sans-serif light, «воздушный» | **condensed, с гравировкой**: caps + tracking 0.12–0.28 |
| Фон | вертикальный градиент | **плоский** `#0A0A0B` (градиент читался как «карточка») |

### 2.3 Геометрия и отступы

- Центр `(233, 233)`, R = 233, безопасный радиус **209 px**. Все прямоугольники проверяются
  юнит-тестом `fits()`.
- **Обод (bezel)** занимает annulus `r = 188…208` px. Отсюда два правила:
  - **залитые/видимые элементы** (строки, график, легенда, индикатор, разделитель,
    каждая строка телеметрии) — все четыре угла внутри `r ≤ 188`, чтобы не касаться рисок шкалы;
  - **текстовые полосы** (заголовок, метрики, фаза, строки экрана 1) — внутри `r ≤ 209`:
    буквы занимают середину полосы, а не её углы, поэтому строка может быть шире, чем её полоса
    в узком месте круга. Там, где полоса подрезана до 188, кегль автоматически ужимается
    (никогда ниже 24 px) — см. `fitText()` в `StatsActivity`.
- Ширины элементов (px, фактические в коде; проверены `GeometryV2Test`):

| Элемент | Ширина | Полоса y |
|---|---|---|
| индикатор раздела | 64 (группа 56) | 60–72 |
| заголовок экрана 2 | 249 | 96–124 |
| заголовок экрана 3 | 257 | 96–124 |
| версия (справа, правый край 365) | 120 | 100–122 |
| строка-леджер (ПУЛЬТ) | **296** | 132–348 |
| гипнограмма | **320** | 164–286 |
| легенда фаз | 300 | 292–316 |
| фаза подъёма | 179 | 348–396 |
| телеметрия 1 / 2 | 240 / 170 | 350–376 / 374–400 |
| герой (текст «07:12») | ~226 (полоса 401) | 182–290 |
| дуга-рычаг | annulus **152…186** | θ 52°…128° |

- **Внешние отступы**: текст — 0 px от края круга по вертикали не бывает: минимальный зазор
  до края 24 px (по построению радиуса 209), до обода — 8 px.
- Внутренние отступы строки-леджера: 16 px слева/справа от её ширины, вертикальный центр.
- Между смысловыми блоками по вертикали: **≥ 8 px**, между блоком и рычагом — **≥ 6 px**.

### 2.4 Движение

| Событие | Длительность | Кривая |
|---|---|---|
| Жест «следующий раздел» — контент за пальцем | 1:1 (`translationX = dx`), затемнение до `alpha 0.78` | — |
| Отмена жеста (возврат) | **140 мс** | decelerate |
| Доводка жеста + старт следующего экрана | **180 мс** + slide **220 мс** | decelerate |
| Нажатие рычага | **0 мс** (мгновенная смена цвета) | — |
| Отпускание рычага | **120 мс** | decelerate |
| Дыхание янтаря при записи | **1400 мс**, цикл | ease-in-out (alpha 0.55→1.0, точка r 7→13 px) |
| Смена значения (окно/повтор/отложить) | **0 мс** («детент») + хаптик `tick` | — |
| Появление/исчезновение дуги при взведении | **0 мс** | — |
| AOD | обновление **1 раз в минуту**, анимаций нет | — |

**Fade-переходов между разделами нет** — только следование за пальцем и slide (R12). Хаптика:
`tick` — на детент и на подтверждённый свайп, `confirm` — на главном действии; в AOD — молчание.

## 3. Карта экранов

Общая рамка на всех трёх экранах: обод `r 188…208`, индикатор раздела в полосе `y 60…72`
(выше нельзя: на `y 42` уже нет точек внутри `r = 188`, и индикатор наезжает на шкалу).

**Индикатор раздела** (`SectionIndexView`): три риски высотой **3 px**, толщина **2 px**,
шаг **12 px** (активная длиннее: 16 px), вся группа центрирована, ширина группы ≤ **48 px**.
Активная риска `ember`, неактивные `#2A2D31`. Раздел 1 — левая риска, 2 — средняя, 3 — правая.

### 3.5 Навигация (R11–R13)

- Свайп **влево** из центральной зоны (старт > 70 px от края, |dx| ≥ 90 px, |dx| > 1.4·|dy|) —
  следующий раздел: 1 → 2 → 3 → **1** (циклически).
- Свайп **вправо** — предыдущий: 1 → 3 → 2 → 1 (циклически, R13).
- Переход между Activity: контент уходит за пальцем, затем `overridePendingTransition` со
  `slide_*` 220 мс. Назад (влево-свайп от левого края) остаётся системным — не перехватываем.
- Стек: `CLEAR_TOP | SINGLE_TOP` при каждом переходе, чтобы порядок разделов не расползался;
  «назад» внутри раздела — `finish()` только когда предыдущий раздел уже лежит снизу.

## 4. Компоненты

### 4.1 `NightDialView` (обод + герой + рычаг), файл `NightDialView.kt`

Обод рисуется общим кодом `Bezel.drawTicks`: та же шкала, что на экранах 2–3, обязана совпадать
пиксель в пиксель — иначе «один прибор» распадается на три разных экрана.

Один View 466×466 (`MATCH_PARENT`), рисует всю «приборную панель» экрана 1. Всё считается от
`min(w,h)`, чтобы работал и в превью, но спроектировано под 466.

- **Шкала**: 72 риски через 5°; первая на угле 0° = 12 часов (вверх). Minor: `r 197…203`, 2 px,
  `bezel_minor`; major (каждая 6-я = час): `r 197…208`, 2 px, `bezel_major`.
  *Обоснование*: 72 деления = 10 минут на деление — ровно тот шаг, который читается на 466 px
  (17.5 px между рисками) и не превращается в «штрихкод».
- **Дуга отсчёта**: `r 188…192`, 4 px, `ember`, `strokeCap = ROUND`, старт на угле текущего
  времени, sweep = `осталось / 12 ч × 360°` (`coerceIn(0, 360)`). *Обоснование*: длина дуги равна
  времени ожидания — на циферблате это физическая величина, а не абстрактный процент.
- **Точка** на конце дуги: Ø 12 px `ember_hot`; при записи — дыхание Ø 7→13 px, 1400 мс.
- **Маркер «сейчас»**: линия `r 195…207`, 3 px, `paper_2` — чтобы «сейчас» было видно, даже
  когда дуга замкнута в круг.
- **Тексты** — canvas, `sans-serif-condensed`, центрированы по X, базовая линия по полосам:
  «сейчас» (36 px, ls 0.16, `paper_3`), «ПОДЪЁМ» (32 px, ls 0.28, `paper_3`),
  герой (104 px, ls −0.02), state (36 px, ls 0.12), detail (30 px, ls 0.10).
- **Рычаг**: annulus-сектор `r 152…186`, θ ∈ [52°, 128°] (отсчёт от вертикали «вниз»).
  Текст по дуге (по буквам, `r 189`, 26 px, ls 0.12). Состояния: `OFF` (`ember_ash` + `ember`),
  `ARMED` (`ember` + `on_ember`), `STOP` (`signal_stop` + `on_stop`), `PRESSED` — цвет на 12 %
  светлее (мгновенно). *Обоснование*: кривой текст убирает конфликт «подпись vs дуга» и делает
  кнопку цельным инструментом.
- **Hit-зоны** (считаются в `onTouchEvent`, без дочерних View):
  - рычаг: `r ∈ [110, 209]` ∧ |θ| ≤ 46° → `onPrimaryTap()`, эффективная площадь ~96 × 250 px;
  - герой: `|x−233| ≤ 130` ∧ `y ∈ [182, 300]` → `onTimeTap()` (редактор времени);
  - долгое нажатие (≥ 400 мс) в любой точке → `onTimeTap()`.
- **AOD**: `setDimmed(true)` — фон `#000000`, риски в AOD **не рисуются** (при 30 % они давали
  на чёрном около `(10,11,12)` — контраст 1.1:1, то есть «тонкого кольца» не было), поверх рисуется
  отдельное кольцо 1 px `paper_3` alpha 205 на `r = 193` (на `r = 200` кольцо занимало 79 % окружности и «съедало» риски — замерено); дуга отсчёта — 2 px `ember_dim`;
  тексты 88 px `paper_2` + мелкая строка «сейчас» 24 px; рычаг/подписи не рисуются; анимации глушатся.

### 4.2 `ArcLever` — часть `NightDialView`

Отдельного класса не нужно: hit-тест annulus-сектора — 12 строк, а общая canvas-сессия позволяет
рисовать рычаг под текстами в правильном порядке (обод → дуга → рычаг → тексты). Рычаг живёт **внутри** обода: иначе он закрывает маркер «сейчас» и дугу отсчёта, когда текущее время попадает в нижний сектор (проверено на устройстве).

### 4.3 `HypnogramView` (экран 2), файл `HypnogramView.kt`

- Размер: **320 × 122 px** (y 164…286). Фон прозрачный, карточки нет.
- Базовая линейка: `y = h − 1`, 1 px, `rule`, от `x = 0` до `w`.
- **Гребёнка фаз**: шаг **4 px** (≈ 1 бакет = 30 с ⇒ 4 px), ширина столбика **2 px**, растёт вверх
  от базовой линии. Высоты: `DEEP 76`, `LIGHT 48`, `AWAKE 10`, `UNKNOWN 4`.
  Цвета: `ember` / `ember_dim` / `phase_awake` / `phase_none`.
  *Обоснование*: фазы на этих часах **оценочные** — гребёнка читается как «оценка высоты», а не
  как медицинская полоса; высота и яркость заменяют цвет (принцип 3).
- **Линия пульса**: `paper_3`, 1.5 px, полилиния с разрывами при `hr ≤ 0`, в полосе `y 0…40`
  (над гребёнкой; самый высокий столбик начинается с `h − 77 = 45`), `hrMin−5 … hrMax+5` →
  линейное отображение. *Обоснование*: измерение — светлая линия, оценка — янтарь; не путаются.
- Пустое состояние: по центру 30 px `paper_3` «НЕТ ДАННЫХ».

### 4.4 `LedgerRow` (экран 3), файл `LedgerRow.kt`

Кастомный `View` **296 × 72**: подпись 26 px caps ls 0.18 `paper_2` слева в 16 px от края, значение
34 px caps `paper` справа в 16 px; разделитель 1 px `rule` по низу на всю ширину.
`isActive` → значение `ember`. Тап: haptic `tick` + `onTap()`. Вся строка — hit-зона 72 px (R3).

### 4.5 `SectionIndexView` (все экраны), файл `SectionIndexView.kt`

Группа — **56 px** (16 + 12 + 8 + 12 + 8), View 64 × 12 px, центрируется по фактической сумме
длин (активная риска может стоять в любой позиции). Три риски 2 px: активная 16 px `ember`,
остальные 8 px `#2A2D31`, зазор 12 px.
Ставится в полосу `y 60…72` центрированным (выше нельзя — уйдёт за `r = 188` в обод).
Никакой анимации: смена раздела = смена экрана.

### 4.6 `SwipeSections` (навигация), файл `SwipeSections.kt`

Единый помощник для трёх Activity: `attach(activity, sectionIndex, contentView)`. Считает жест
по правилам R11 (старт > 70 px от края, |dx| ≥ 90 px, |dx| > 1.4·|dy|), тянет `contentView`
за пальцем (`translationX = dx`, `alpha = 1 − 0.22·|dx|/233`), отменяет за 140 мс, коммитит
за 180 мс и запускает нужный раздел через `CLEAR_TOP | SINGLE_TOP` со slide-анимацией 220 мс.
Цикл: `next = (i % 3) + 1`, `prev = ((i + 1) % 3) + 1`.

## 6. Чек-лист приёмки на устройстве (OPW2, 466×466)

**Как мерить.** `adb -s 192.168.31.137:<порт> shell input keyevent KEYCODE_WAKEUP` →
`uiautomator dump /sdcard/ui.xml` + `pull` → по каждому узлу с непустым текстом посчитать
`√((x−233)² + (y−233)²)` для всех четырёх углов `bounds`; максимум ≤ **209**.
Скриншоты — `exec-out screencap -p` (чёрный PNG ровно 1866 байт = экран спал, повторить).
Геометрия внутри canvas-компонентов проверяется юнит-тестом `GeometryV2Test` + скриншотом.

- [ ] **R1**: ни один узел UI и ни одна нарисованная деталь не выходят за 209 px от центра
      (обод снаружи 208 px, рычаг снаружи 186 px — внутри обода).
- [ ] **Шкала**: 72 риски, шаг между соседними 17.5 ± 1 px по хорде на `r 200`; часовые риски
      в 2 раза длиннее; на 12 часов риска совпадает с вертикальной осью.
- [ ] **Дуга отсчёта**: при взведении стартует на угле текущего времени и заканчивается ровно
      у положения времени подъёма `(h·60+m) mod 720 / 720 · 360°` ±2°. Проверить для 23:40 → 07:12
      и для 07:00 → 08:00 (короткая дуга).
- [ ] **Герой**: высота строки времени ~104 px (замерить по скриншоту), цвет `#FFA24C` во
      взведённом состоянии, `#F2EDE6` — в невзведённом.
- [ ] **Рычаг**: видимая дуга 34 px по радиусу, угловой размер 76° ±4°, текст по дуге читается
      без наклона головы (буквы ориентированы по радиусу); при нажатии цвет меняется мгновенно.
- [ ] **Тап-зоны**: рычаг — касание в 10 px над видимой дугой тоже срабатывает; герой — тап по
      времени открывает `AlarmSetupActivity`; в ПУЛЬТЕ — тап в любую точку строки 72 px меняет
      значение.
- [ ] **Одно главное действие**: на экране 1 ровно один залитый акцентом элемент (рычаг).
- [ ] **Состояния словами**: 4 состояния экрана 1 различимы **текстом** в ч/б:
      `НЕ ВЗВЕДЁН`, `ВЗВЕДЁН`, `ЗАПИСЬ · N%`, `НЕТ ПРАВ`.
- [ ] **Ambient**: `adb shell am start -n io.github.smartalarm/.HomeActivity --ez force_ambient true`;
      в кадре только два времени, шкала (alpha 30 %) и тонкая дуга; фон ровно `#000000`;
      кнопок, подписей, пульса нет.
- [ ] **Переходы**: при свайпе контент идёт за пальцем 1:1, затемнение до alpha 0.78;
      доводка 180 мс; между экранами **нет плавного появления** (fade отсутствует).
- [ ] **Цикличность**: 1 → 2 → 3 → 1 свайпом влево и 1 → 3 → 2 → 1 свайпом вправо;
      после трёх переходов стек не растёт (`adb shell dumpsys activity activities | grep opw2`).
- [ ] **Края**: между текстом и краем круга ≥ 20 px на всех трёх экранах.
- [ ] **Шрифты**: минимум 24 px; герой 104 px; заголовки 28 px; ни одного 8–10 sp, как в v1.
- [ ] **Функции целы**: запись ночи стартует и пишет CSV; `alarm_state`/`wake_phase` пишутся;
      срабатывание в окне ±N мин работает; snooze 5/10/15 меняется из ПУЛЬТА и из экрана
      будильника; повтор по дням меняется; AOD не выжигает экран (нет статичных ярких пятен
      на 200+ px, кроме времени — оно меняется).
- [ ] **Батарея**: за 1 час AOD c новым экраном расход не выше, чем у v1 (нет анимаций в AOD,
      обновление 1/мин).
